# Upload redesign meeting, 28 Oct

Present: Aiko (platform), Bram (mobile lead), Celeste (security), Dev (API)

- Dev: proposal is signed upload URLs. App asks the API for one short-lived
  signed URL per photo, uploads each photo straight to object storage, then
  submits the inspection with just the photo keys. The API never touches photo
  bytes.
- Celeste: OK with signed URLs if they expire in 15 minutes, are scoped to one
  object key each, and the API checks each key exists and belongs to that
  inspection before accepting the submit. No listing permission.
- Bram: per-photo uploads let the app retry one photo instead of everything.
  Big win on bad connections. Needs a new upload queue in the app; about three
  sprints. Ships in app 4.12.
- Aiko: raising the gateway timeout is off the table (security). Chunking the
  request through the API keeps photo bytes on our servers and still needs the
  two extra servers.
- Dev: the old submit endpoint has to stay up for apps that haven't updated.
- Bram: problem is about 9% of inspectors are on devices stuck on iOS 15, and
  4.12 needs iOS 16 because of the background upload API. Those inspectors
  can't update to 4.12 at all.
- Aiko: keeping the old endpoint means keeping the photo-buffering servers.
  That's the two September servers plus their share of the base fleet, roughly
  GBP 1,800 a month.
- Open: do we force-upgrade (old endpoint switched off on 31 Jan, older app
  versions blocked) or keep the old endpoint running for old clients
  indefinitely? Bram and Aiko disagree. Needs the review to decide. Either way
  the mobile team needs the answer before sprint planning on 16 Nov, because a
  forced upgrade needs an in-app upgrade prompt in 4.12.

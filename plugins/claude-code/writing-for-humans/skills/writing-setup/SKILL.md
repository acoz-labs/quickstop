name: writing-setup
description: Verify or troubleshoot Writing for Humans installation and automatic activation, including native enablement, trust and configuration conflicts.
---

Use this for setup or diagnostics, not ordinary writing. Read the bundled [harness setup reference](references/setup.md). Identify the active harness, version, execution mode and installation scope before suggesting changes. If the package is unavailable, follow its README bootstrap instructions first.

Report separately what is installed, enabled, trusted where applicable, loaded, and behavior-verified. Inspect only relevant configuration through native commands/settings interfaces. Do not print secrets, private instruction contents or entire configuration files. A manifest or successful handler invocation does not prove model application. Use a fictional writing task with explicit supplied facts in the actual session. Compare its output against those facts before calling behavior verified: check invented causes, changed uncertainty or status, exact values and added requirements as well as clarity. A fluent response that invents a cause fails this check. Name any untested subagent, resume or compaction paths honestly.

Explain the smallest corrective action and its scope. Preserve unrelated configuration, existing instruction files and selected styles. Never bypass native trust, fabricate trust hashes or copy the core into global instructions. Report organization-managed restrictions as limits.

Native enablement is the normal solution. If evidence demonstrates a necessary configuration edit, explain its exact fields, scope and effects before applying it within the user's authorization. Record only the original values needed to undo changes you own, preserving private recovery data locally. Reruns must not duplicate entries. On removal, detect intervening user edits; never overwrite newer configuration with a whole-file backup. Runtime handlers never invoke this skill or modify consumer configuration.

After correction, verify native loading and a representative writing result. Report remaining limits and how to disable or remove the integration. Do not claim universal coverage or perfect model compliance.

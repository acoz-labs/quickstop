# Optional solution plans

A clear bounded issue is sufficient for ordinary changes. Maintainers author a
plan when complexity or risk warrants one, incorporating contributor findings.
One README can cover context, decision, design, validation and handoff. Split it
only when useful. A separate planning PR and product-owner sign-off are not
required. Preserve explicit task stopping points and resolve ordinary choices
internally. Update permanent docs from shipped behavior and retire completed
plans; Git history preserves the journey. Existing larger plans remain usable.

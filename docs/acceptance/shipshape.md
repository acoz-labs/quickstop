# Shipshape Codex acceptance — pending

This is a procedure, not an acceptance receipt. Package checkpoint P contributor
tests are static/CLI fixtures only. Native installed-cache proof, independent
author/reviewer/correction fixture, integration, fixed merged candidate acceptance
and publication are pending. First public release waits for full integrated
acceptance of the assigned issue. Do not add a release pointer from these checks.

Use the existing delivery criteria and gates in [delivery](../delivery.md) and
[local verification](../operations/local-verification.md); this document adds no
self-judging gate. Preserve Claudit/Writing payloads, native indexes and release
lock while authoring candidate bytes.

- `plugin-installation`: independently retain the fixed merged candidate archive
  and package digest. In an isolated supported Codex version, use its actual
  native plugin procedure to install those exact retained bytes. Record commands,
  harness/tool versions, installed-cache digest, fresh-session discovery of all
  three skills, and helper execution resolved from installed paths. Verify disable,
  uninstall and fresh-session absence, then recovery to the accepted pin. An
  unavailable native host is a blocker. Static manifest checks are insufficient.
- `assigned-plugin-scenarios`: a distinct reviewer in fresh context and a clean
  exact-head workspace executes the real fixture, detects an intentionally seeded
  defect, and records findings. The author corrects without weakening tests. A
  new head requires independent executed re-review; reviewer-written fixes need
  another reviewer. Exercise two correction rounds then replan, interruption,
  duplicate/reordered events, uncertain effects, and bounded durable handoff
  outside a fixture consumer root. Capture actual commands, exit outcomes,
  evidence locators/digests and process/session separation. Supplied role strings
  do not prove provenance. Missing access or sandbox capability blocks acceptance.
- `consumer-state-boundaries`: compare consumer bytes/config/state before and
  after proposal-only and stronger-rule tasks. Confirm no implicit adoption,
  upgrades, credentials, services, network, PR or publication effects. Validate
  changed spec/config/package/tool/base/head/generation invalidation, stale review,
  contradictory success, symlink/traversal outputs, replay and unrelated attempts.
  Tool resolution is read-only. Payload prose never becomes commands.
- `issue-criteria`: freeze the actual integrated merged SHA and complete PR set.
  Independently exercise that retained artifact through the assigned issue's full
  integration lifecycle and existing nomination/acceptance/release gates. Record
  limitations and actual merged candidate identity. Package fixtures alone cannot
  establish integration, acceptance or factory delivery.

Static contributor checks: pinned Python `bin/ci`, marketplace base comparison,
whitespace, exact portable manifest subset, resource containment and unchanged
advertisement projections. These are distinct from native and independent proof.
After acceptance, separately review publication pointers, publish the same retained
bytes, verify downloaded and installed digests and source/tag identity, and record
initial-release recovery with the existing release receipt procedure.
